# HDU Library AutoBook · 杭电图书馆自动预约

来源：[ZRui-C/HDU_AUTO_BOOK-public](https://github.com/ZRui-C/HDU_AUTO_BOOK-public)，基于 V2 分支。原始说明保存在 README.original.md。

每天只预约四楼，默认预约后天对应星期的时段。电脑需在北京时间 **19:55 前开机、联网并保持 Windows 用户登录**；可以锁屏。图书馆账号由脚本自动登录。

## 选座规则

四楼后台 ID = 页面座位号 + 62564，1–332 号对应 62565–62896。优先级从高到低，每一等级内部单独随机：

| 等级 | 四楼座位号 | 后台 ID 区间（含两端） | 数量 |
|---|---|---|---|
| 特等座 | 17–58 | 62581–62622 | 42 |
| 一等座 | 307–332 | 62871–62896 | 26 |
| 二等座 | 1–16、59–306 | 62565–62580、62623–62870 | 264 |

成功即停止；实时查询确认四楼目标时段无位时，立即结束当天计划。等级顺序不会被随机打乱，四楼以外的地图座位不会进入候选列表。已存在覆盖目标时段的四楼预约时查单确认并结束；已有其他楼层的覆盖订单会提示处理，不自动取消订单。

`user_config.yml` 使用区间，不需要写 332 行数字：

```yaml
自定义:
  房间: 四楼
  优先级:
    - 名称: 特等座
      区间: [[62581, 62622]]
    - 名称: 一等座
      区间: [[62871, 62896]]
    - 名称: 二等座
      区间: [[62565, 62580], [62623, 62870]]
```

程序在内存中展开区间，校验范围、重叠和等级顺序；旧版整数列表仍支持。

## 五轮定时预约

Windows 只保留一个启用的任务 `HDU-Library-Daily`，19:55 启动并提前登录、查单，整个过程复用 HTTP 会话。

| 轮次 | 北京时间 |
|---|---|
| 1 | 20:00:00 |
| 2 | 20:00:30 |
| 3 | 20:01:30 |
| 4 | 20:04:00 |
| 5 | 20:10:00 |

这些是最多五轮预约机会，每轮可在允许的座位内顺序换座，最多成功创建一个目标时段订单。成功、已有覆盖订单或四楼无位会提前结束，故通常不会执行满五轮。

- 第一轮整点先直接尝试一个随机特等座，避免地图查询阻塞首个请求；被占用后才查询实时空位，按特等座、一等座、二等座顺序继续。
- 后续轮次先刷新四楼可用座位，再按等级内部随机顺序提交。
- 每轮新预约请求预算 20 秒，达到预算停止新增请求；最晚不在20:15后新增预约请求。查单仍用于确认可能已被服务器接受的请求。
- 整点后 4 秒内遇到明确的窗口未开放提示，最多重试 3 次，间隔 0.4、0.8、1.6 秒。限流则停止本轮；提交网络异常先查单，避免盲目重复提交。
- `.local/daily-state-日期.json` 记录已执行轮次。进程重启不重复执行已记录的轮次，过期轮次跳过。
- 同时运行的进程由文件锁阻止。旧的 20:00/20:02 等独立任务已移除。

五轮时间在 `user_config.yml` 的 `自动预约.运行时间` 配置，必须是五个递增的时间，第一轮20:00:00，最后不晚于20:15:00。电脑晚开机时仅执行尚未过期的轮次。

| 预约日期 | 启用 | 开始 | 持续 |
|---|---|---|---|
| 周一 | true | 15:00 | 7小时 |
| 周二 | true | 16:00 | 6小时 |
| 周三 | true | 10:00 | 12小时 |
| 周四 | true | 15:00 | 7小时 |
| 周五 | true | 13:00 | 9小时 |
| 周六、周日 | false | — | — |

以上按**预约日期**读取，例如周一晚读取周三配置。各天 `name` 都是 `自定义`。

## 运行和验证

```powershell
# 安装/更新并启用本机日任务
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-Schedule.ps1

# 启动当天的五轮计划；过期轮次会跳过
.\.venv\Scripts\python.exe .\main.py --daily

# 只读检查：四楼，默认后天，以下指定15:00起7小时，不提交预约
.\.venv\Scripts\python.exe .\main.py --check --start 15 --hours 7

# 预约逻辑离线回归，不登录、不提交
.\.venv\Scripts\python.exe -m unittest test_main test_seat_plan test_submission_safety test_native_schedule test_cas_auth

# DeepSeek 协作工具离线回归，不调用付费 API
.\.venv\Scripts\python.exe -m unittest discover -s scripts -p test_deepseek_collab.py
```

配置文件按 UTF-8 读取，路径相对脚本目录。`.local/credentials.xml` 使用 Windows DPAPI 加密，只有当前 Windows 用户在当前电脑可解密；可运行 `Save-Credential.ps1` 重新保存。本机凭据、日志和虚拟环境都已被 Git 忽略。`SCHOOL_ID`、`PASSWORD` 环境变量优先于本机凭据。

本机日志位于 `logs/YYYY-MM-DD.log`，订单结果写入 `.local/booking-*.json`。新单核验所有者、有效状态、精确时段及座位；已有覆盖单允许时间更长，但详情必须覆盖目标时段并位于允许座位池。恢复确认的订单明确标记为 `recovered`，不会当成本轮新建成功。验证码或密码错误不会通过反复尝试解决。不能保证外部网络、学校服务和热门座位竞争下每次都预约成功。

### 提交结果未知时的恢复

预约 POST 前，脚本先把账号级待确认记录原子保存到 `.local/pending-*.json`。超时、非 JSON、异常结构、成功但缺少订单编号、订单详情核验失败时，都保留记录并停止新增提交；收到订单号时先保存编号，再核验详情。即使当天轮次已记录完成，重启后也会优先登录并只读恢复未决记录。

已核验订单另存 `.local/verified-*.json`，然后才清除 pending；若服务端列表暂未显示订单，下次仍可根据该提示重新查询详情，避免忘掉刚确认的订单。明确的座位占用、未开放等拒绝响应仍遵循原有有限换座或退避。单独出现“稍后”等模糊信息不构成未成交证据。

如果始终无法确认，脚本保持停止新提交，需先在网页核对再人工处理本地记录；不要直接删除待确认文件来强行重试。这项取舍优先避免重复提交，可能减少网络异常后的自动补跑机会。

这些记录与文件锁只在当前工作目录有效。GitHub 全新 runner 不会自动继承上个 job 的文件，也不与其他仓库或电脑共享记录，仍需后续设计主端接管或共享租约。
